**GitHub Issues вимкнено**: API повертає HTTP 410 `Issues has been disabled in this repository`. Це тимчасовий журнал до увімкнення Issues у налаштуваннях репозиторію. Не створювати для кожного завдання дубль PR без файлів.

## Правила для паралельних перекладачів

1. Перед роботою прочитати актуальний `master`, усі відкриті PR, журнали та гілки.
2. До початку редагування заявити `CLAIM: <точний файл / номери віршів>; <виконавець>; <дата>; <планована дата завершення>` в коментарі до відповідного PR (після ввімкнення Issues — в issue).
3. Не редагувати файли, зайняті іншим активним CLAIM. Якщо є дубль — узгодити в коментарях, а не робити незалежний конкурентний переклад.
4. Один PR — окремий завершений внесок; текст книжки, академічні коментарі, права й CI не змішувати.
5. Для кожного вірша зберігати ID, джерело санскриту й точне походження проміжного перекладу. Коментар редактора — окремо від основного тексту.
6. Перед merge: відомі права, редакторська звірка, перевірені номери віршів, успішна збірка PDF для `.tex`, актуальна гілка, перевірений diff і head SHA.
7. До завершення звіряння текст має статус **чернетка**; називати «повним перекладом» лише тоді, коли перевірена відповідність всім розділам і віршам.
